# Apache Web Server Down Troubleshooting Lab

## Objective

Practice troubleshooting a web service outage where the Ubuntu Server remains reachable over the network, but the hosted website is unavailable because the Apache web server has stopped.

---

## Lab Topology

| Device | IP Address | Role |
|---------|------------|------|
| Ubuntu Server | 10.0.0.10 | Apache Web Server |
| Ubuntu Desktop | 10.0.0.20 | Client |
| Kali Linux | 10.0.0.30 | Security/Testing |

---

# Scenario

Users report that they cannot access the company website hosted on the Ubuntu Server.

Initial assumptions:

- The server is powered on.
- Network configuration is correct.
- DNS is functioning.
- SSH access is available.

The goal is to identify why the website is unavailable and restore service.

---

# Intentionally Breaking the Lab

On the Ubuntu Server, stop the Apache service:

```bash
sudo systemctl stop apache2
```

Verify that the service has stopped:

```bash
sudo systemctl status apache2
```

Expected output:

```
Active: inactive (dead)
```

---

# Symptoms Observed

From the Ubuntu Desktop:

### Ping Test

```bash
ping 10.0.0.10
```

Result:

- Successful replies
- Network connectivity confirmed

---

### HTTP Test

```bash
curl http://10.0.0.10
```

Result:

```
Connection refused
```

The website also fails to load in a web browser.

---

### SSH Test

```bash
ssh vboxuser@10.0.0.10
```

Result:

- SSH login successful

This confirms:

- The operating system is running.
- The server is reachable.
- The issue is isolated to the web service.

---

# Troubleshooting Process

## 1. Verify Apache Status

```bash
sudo systemctl status apache2
```

Observed:

```
Active: inactive (dead)
```

Conclusion:

The Apache service is not running.

---

## 2. Verify Listening Ports

```bash
sudo ss -tlnp
```

Observed:

- Port 22 (SSH) is listening.
- Port 80 (HTTP) is missing.

Conclusion:

No service is accepting HTTP connections.

---

## 3. Review Service Logs

```bash
sudo journalctl -u apache2
```

The logs showed that Apache had been stopped successfully.

No configuration errors or crashes were present.

---

# Resolution

Restart Apache:

```bash
sudo systemctl start apache2
```

Verify:

```bash
sudo systemctl status apache2
```

Expected:

```
Active: active (running)
```

---

## Verify Port 80

```bash
sudo ss -tlnp
```

Observed:

```
*:80
```

Apache is now listening for HTTP requests.

---

## Verify From Client

```bash
curl http://10.0.0.10
```

Result:

- HTML returned successfully

The website also loads normally in a web browser.

---

# Root Cause

The Apache web service had been stopped.

Although the server remained reachable over the network and SSH was functioning, no application was listening on TCP port 80 to handle incoming HTTP requests.

---

# Troubleshooting Methodology

1. Verify basic network connectivity using `ping`.
2. Test the affected application using `curl`.
3. Confirm the server is reachable via SSH.
4. Check the Apache service status.
5. Verify that port 80 is listening.
6. Review service logs.
7. Restart the service.
8. Confirm the website is accessible.

# Key Takeaways

- Successful ping does **not** guarantee an application is running.
- SSH access confirms the operating system is available but does not verify other services.
- Checking service status should be one of the first steps when troubleshooting application outages.
- Verifying listening ports quickly identifies whether a service is actively accepting connections.
- Following a structured troubleshooting process makes diagnosing service outages faster and more reliable.
