# Network Troubleshooting Lab - Apache Wrong Port

## Objective

Practice troubleshooting an Apache web server that is running correctly but is configured to listen on the wrong TCP port.

The goal was to identify why HTTP connections to the server's standard port were failing, determine which port Apache was actually using, and restore the service to port 80.

---

## Lab Environment

| VM             | Role                      | IP Address  |
| -------------- | ------------------------- | ----------- |
| Ubuntu Server  | Web Server                | `10.0.0.10` |
| Ubuntu Desktop | Client                    | `10.0.0.20` |
| Kali Linux     | Client / Security Testing | `10.0.0.30` |

Apache was installed and configured on the Ubuntu Server.

### Expected Configuration

```text
Apache → TCP Port 80
```

---

## Initial Verification

Before intentionally breaking the configuration, I verified that Apache was working normally.

### Check Apache Status

```bash
sudo systemctl status apache2
```

Apache was confirmed to be:

```text
Active: active (running)
```

### Check Listening Ports

```bash
sudo ss -tlnp | grep apache
```

Apache was initially listening on TCP port `80`.

### Test From Ubuntu Desktop

```bash
curl http://10.0.0.10
```

The request successfully returned the Apache web page.

This established a known-good baseline before introducing the failure.

---

## Creating the Problem

### 1. Backed Up Apache Configuration

```bash
sudo cp /etc/apache2/ports.conf /etc/apache2/ports.conf.bak
```

### 2. Changed Apache's Listening Port

Edited:

```bash
sudo nano /etc/apache2/ports.conf
```

Changed:

```text
Listen 80
```

to:

```text
Listen 8080
```

### 3. Changed the Virtual Host Port

Edited:

```bash
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Changed:

```text
<VirtualHost *:80>
```

to:

```text
<VirtualHost *:8080>
```

### 4. Verified the Configuration

```bash
sudo apache2ctl configtest
```

Output:

```text
Syntax OK
```

### 5. Restarted Apache

```bash
sudo systemctl restart apache2
```

Apache remained active and running.

---

## Troubleshooting

### Step 1 - Test Network Connectivity

From Ubuntu Desktop:

```bash
ping 10.0.0.10
```

The server was reachable, indicating that basic network connectivity was functioning.

### Step 2 - Test HTTP

```bash
curl http://10.0.0.10
```

### Step 3 - Check Apache Service

On Ubuntu Server:

```bash
sudo systemctl status apache2
```

Apache was still running.

This ruled out Apache being stopped as the cause.

### Step 4 - Check Listening Ports

```bash
sudo ss -tlnp | grep apache
```

The output showed that Apache was listening on:

```text
*:8080
```

rather than:

```text
*:80
```

### Step 5 - Test the Correct Port

From Ubuntu Desktop:

```bash
curl http://10.0.0.10:8080
```

The request succeeded and returned the Apache web page.

---

## Root Cause

Apache was running normally, but its configuration had been changed to listen on **TCP port 8080 instead of the standard HTTP port 80**.

The network itself was functioning correctly.

The troubleshooting process identified the issue by working through the layers:

```text
Client
  ↓
Network connectivity
  ↓
Server reachable
  ↓
Apache running
  ↓
Apache listening port
  ↓
Port 8080 instead of port 80
```

---

## Resolution

Restored Apache's configuration to use TCP port 80.

### Restore `ports.conf`

```bash
sudo nano /etc/apache2/ports.conf
```

Changed:

```text
Listen 8080
```

back to:

```text
Listen 80
```

### Restore Virtual Host

```bash
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Changed:

```text
<VirtualHost *:8080>
```

back to:

```text
<VirtualHost *:80>
```

### Verify Configuration

```bash
sudo apache2ctl configtest
```

Expected:

```text
Syntax OK
```

### Restart Apache

```bash
sudo systemctl restart apache2
```

### Verify Listening Port

```bash
sudo ss -tlnp | grep apache
```

Apache was once again listening on TCP port `80`.

## Key Takeaway

A service being **active and running does not necessarily mean it is accessible where you expect it to be**.

When troubleshooting a connection failure, it is important to determine:

1. Can the client reach the server?
2. Is the service running?
3. Is the service listening?
4. Which port is the service listening on?
5. Is the client connecting to the correct port?

In this lab, Apache was healthy, but it was listening on the wrong port. Checking the listening sockets with `ss` revealed the misconfiguration and allowed the issue to be resolved.
