# Scenario 05 - DNS Resolution Failure

## Objective

Practice diagnosing and resolving a DNS resolution issue while verifying that the underlying network connectivity remains functional.

---

## Lab Environment

### Virtual Machines

| Machine | Role | IP Address |
|---------|------|------------|
| Ubuntu Server | Web/SSH Server | 10.0.0.10 |
| Ubuntu Desktop | Client | 10.0.0.20 |
| Kali Linux | Testing Machine | 10.0.0.30 |

### Network Interfaces (Ubuntu Desktop)

| Interface | Purpose | Configuration |
|-----------|---------|---------------|
| **enp0s3** | NAT Adapter (Internet Access) | DHCP |
| **enp0s8** | Internal Network | Static IP (10.0.0.20) |

---

# Initial Investigation

Before making any changes, I verified which interface was responsible for DNS resolution.

```bash
resolvectl status
```

## Output

### enp0s8

```text
Current Scopes: none
Default Route: no
```

This confirmed that the internal network interface was **not** providing DNS resolution or internet connectivity.

### enp0s3

```text
Current Scopes: DNS
Protocols: +DefaultRoute
Current DNS Server: 192.168.1.1
DNS Servers: 192.168.1.1
Default Route: yes
```

This confirmed that:

- enp0s3 is the default route.
- enp0s3 handles internet access.
- enp0s3 is responsible for DNS resolution.

---

# Root Cause Planning

Initially, I assumed I should modify the DNS settings on the internal network interface (enp0s8).

After examining the output of `resolvectl status`, I determined that this would not affect hostname resolution because:

- enp0s8 does not have a default route.
- enp0s8 is only used for communication between the lab virtual machines.
- DNS requests are sent through enp0s3.

Therefore, the correct interface to modify for this troubleshooting scenario is **enp0s3**.

---

# Simulating the Failure

On Ubuntu Desktop:

1. Open **Settings**
2. Navigate to **Network**
3. Select **enp0s3**
4. Open **IPv4 Settings**
5. Disable **Automatic DNS**
6. Replace the working DNS server

From:

```text
192.168.1.1
```

To:

```text
203.0.113.53
```

This IP address belongs to a documentation-only network and does not provide DNS service.

# Expected Symptoms

The goal of this lab is to break **DNS only**, while leaving the network itself operational.

Expected:


Expected:

- Success

```bash

```

Result:

```text

```

# Troubleshooting Process

## Verify Interface Configuration

```bash
ip addr
```

Questions:

- Is the interface up?
- Does it have the correct IP address?

---

## Verify Routing

```bash
ip route
```

Confirm the default route still exists.

Example:

```text
default via 192.168.1.1 dev enp0s3
```

---

## Verify DNS Configuration

```bash
resolvectl status
```

Confirm that the configured DNS server matches the intentionally incorrect address.

---

## Test DNS Resolution

```bash
nslookup google.com
```

Result:

```text
connection timed out
```

---

## Test Against a Known Good DNS Server

```bash
nslookup google.com 8.8.8.8
```

Expected:

The query succeeds, proving that:

- Internet connectivity exists.
- The configured DNS server is the problem.

---

# Root Cause

The Ubuntu Desktop client was configured to use an invalid DNS server.

Because DNS resolution failed while IP connectivity remained functional, applications relying on hostnames could not reach remote systems.

---

# Resolution

Restore the original DNS server on enp0s3.

Example:

```text
192.168.1.1
```

Side note: I could've also configured to another valid resolver like ```8.8.8.8```

Reconnect the network interface or reboot the VM.

# Lessons Learned

- Always identify which network interface is responsible for DNS before making configuration changes.
- `resolvectl status` is an excellent tool for determining which interface is providing DNS resolution.
- If `ping` to an IP address succeeds but `ping` to a hostname fails, the problem is likely DNS rather than routing.
- Separate network connectivity testing from DNS testing to isolate issues efficiently.
- Internal network interfaces used for VM-to-VM communication may not participate in DNS or internet routing.
