# Homelab: Duplicate IP Address Troubleshooting

## Objective

Practice identifying and resolving a duplicate IPv4 address conflict in a VirtualBox homelab by using common Linux networking tools and troubleshooting methodology.

---

## Lab Topology

| Machine | Operating System | IP Address |
|----------|------------------|------------|
| Ubuntu Server | Ubuntu Server | `10.0.0.10/24` |
| Ubuntu Desktop | Ubuntu Desktop | `10.0.0.20/24` |
| Kali Linux | Kali Linux | `10.0.0.30/24` |

---

## Scenario

Users report intermittent network connectivity issues. SSH sessions fail randomly, pings occasionally time out, and communication with one workstation is inconsistent.

The root cause is unknown at the start of the investigation.

---

## Introducing the Fault

To simulate a duplicate IP address conflict, Kali Linux was intentionally configured with the same IPv4 address as Ubuntu Desktop.

### Original Configuration

| Machine | IP Address |
|----------|------------|
| Ubuntu Desktop | `10.0.0.20` |
| Kali Linux | `10.0.0.30` |

### Broken Configuration

| Machine | IP Address |
|----------|------------|
| Ubuntu Desktop | `10.0.0.20` |
| Kali Linux | `10.0.0.20` |

Both systems now claim ownership of the same IPv4 address.

---

# Troubleshooting Process

## Step 1 - Verify Connectivity

From Ubuntu Server:

```bash
ping 10.0.0.20
```

### Observed Symptoms

- Intermittent packet loss
- Inconsistent response times
- Unstable communication with the destination host

These symptoms suggested a possible Layer 2 or Layer 3 addressing issue.

---

## Step 2 - Inspect the ARP Cache

To determine which device owned the IP address, the ARP table was inspected.

```bash
ip neigh
```

Example output:

```text
10.0.0.20 dev enp0s8 lladdr 08:00:27:82:fb:5c REACHABLE
```

After additional traffic was generated, the MAC address associated with `10.0.0.20` periodically changed.

Example:

```text
10.0.0.20 -> 08:00:27:82:fb:5c
```

Later:

```text
10.0.0.20 -> 08:00:27:d9:00:15
```

This indicated that two different devices were responding to ARP requests for the same IP address.

---

## Step 3 - Verify Interface Configuration

Each machine's IP configuration was checked.

Ubuntu Desktop:

```bash
ip addr
```

Output:

```text
10.0.0.20/24
```

Kali Linux:

```bash
ip addr
```

Output:

```text
10.0.0.20/24
```

The duplicate IP address was confirmed.

---

## Root Cause

Both Ubuntu Desktop and Kali Linux were configured with the same IPv4 address.

Since Ethernet networks rely on ARP to map IP addresses to MAC addresses, both systems responded to ARP requests for `10.0.0.20`.

As devices updated their ARP caches, traffic was sent to different physical machines, resulting in intermittent connectivity.

---

# Resolution

Kali Linux was restored to its original static address.

| Machine | Correct IP |
|----------|------------|
| Ubuntu Desktop | `10.0.0.20` |
| Kali Linux | `10.0.0.30` |

After correcting the configuration, the ARP cache was cleared.

```bash
sudo ip neigh flush all
```

Connectivity was then verified.

```bash
ping 10.0.0.20
ping 10.0.0.30
```

The ARP table now contained a unique MAC address for each IP.

```bash
ip neigh
```

Example:

```text
10.0.0.20 -> Ubuntu Desktop MAC
10.0.0.30 -> Kali Linux MAC
```

Network communication returned to normal.

# Key Takeaways

- Duplicate IP addresses often produce intermittent connectivity instead of complete network failure.
- ARP tables are valuable for identifying MAC address conflicts.
- Every device on a subnet must have a unique IPv4 address.
- Following a structured troubleshooting methodology makes identifying network issues significantly easier.
