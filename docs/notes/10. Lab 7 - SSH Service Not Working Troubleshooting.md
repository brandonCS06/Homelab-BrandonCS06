# Network Troubleshooting Lab - SSH Service Stopped

## Overview

This lab simulated a common real-world issue where the SSH service on a Linux server is no longer running. Although the server remained online and reachable over the network, remote SSH connections failed because the SSH daemon (`sshd`) was not listening for incoming connections.

The objective was to use a structured troubleshooting process to identify the root cause rather than assuming the problem was network-related.

# Objective

Diagnose and resolve an SSH connectivity issue caused by the SSH service being stopped.

---

# Initial Working State

Before beginning the lab, SSH connectivity was verified from the Ubuntu Desktop.

```bash
ssh vboxuser@10.0.0.10
```

The connection completed successfully, confirming that:

* SSH was running
* Network connectivity was functioning correctly

---

# Breaking the Environment

On the Ubuntu Server, the SSH service was intentionally stopped.

```bash
sudo systemctl stop ssh
```

The service status was verified.

```bash
sudo systemctl status ssh
```

Expected output:


# Observed Symptoms

Attempting to SSH from the Ubuntu Desktop produced:

```bash
ssh vboxuser@10.0.0.10
```

Output:

```text
ssh: connect to host 10.0.0.10 port 22: Connection refused
```

Unlike a firewall issue, the server immediately rejected the connection instead of timing out.

---

# Troubleshooting Process

## Step 1 – Verify Basic Network Connectivity

Ping the Ubuntu Server.

```bash
ping 10.0.0.10
```

Result:

* Ping succeeded
* Network connectivity confirmed

This ruled out:

* Incorrect IP address
* Incorrect subnet mask
* Incorrect default gateway
* Physical connectivity issues

---

## Step 2 – Interpret the SSH Error

The error message was:

```text
Connection refused
```

<img width="484" height="36" alt="image" src="https://github.com/user-attachments/assets/765fb4db-5788-433f-b997-69c5710d9458" />


This indicated that:

* The server was reachable.
* No application was accepting connections on port 22.

This suggested the issue was likely with the SSH service rather than the network.

---

## Step 3 – Verify SSH Service Status

On the Ubuntu Server:

```bash
sudo systemctl status ssh
```

Result:

```text
Active: inactive (dead)
```

Root cause identified:

**The SSH service was stopped.**

---

## Step 4 – Verify Port 22

Check whether anything was listening on port 22.

```bash
sudo ss -tlnp | grep :22
```

Result:

No output.

This confirmed that no service was listening on the SSH port.

---

# Resolution

Start the SSH service.

```bash
sudo systemctl start ssh
```

Verify the service.

```bash
sudo systemctl status ssh
```

Expected output:

```text
Active: active (running)
```

Verify that port 22 is listening.

```bash
sudo ss -tlnp | grep :22
```

Finally, reconnect from the Ubuntu Desktop.

```bash
ssh vboxuser@10.0.0.10
```

The SSH connection was restored successfully.

# Key Takeaways

One of the most important lessons from this lab was understanding the difference between **"Connection refused"** and **"Connection timed out."**

**Connection Refused**

* The destination host is reachable.
* No process is listening on the requested port.
* Common causes include a stopped service or an application not bound to the port.

**Connection Timed Out**

* Packets are being blocked or dropped before reaching the service.
* Common causes include firewall rules, routing problems, or other network connectivity issues.

Although this lab and the previous **Firewall Blocking SSH** lab shared the same symptom ("unable to SSH"), they required different troubleshooting approaches:

| Firewall Blocking SSH      | SSH Service Stopped          |
| -------------------------- | ---------------------------- |
| SSH service running        | SSH service stopped          |
| Port 22 listening          | Nothing listening on port 22 |
| Connection timed out       | Connection refused           |
| Investigate firewall rules | Investigate system services  |

This reinforces the importance of identifying the exact failure point before attempting a fix.
